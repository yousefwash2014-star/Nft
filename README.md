# ⚡ النظام الموحد لمينت الـ NFT فائق السرعة (NFT-Unified)

نظام متكامل وموحد يجمع أقوى ميزات مشروعي `Mint_x_nft-main` و `NFT-main` مع سرعة فائقة في التنفيذ وتناوب ذكي بين روابط الـ RPC ودعم المينت الشامل لضمان عدم تفويت أي فرصة.

---

## 🌟 أبرز مميزات النظام الموحد

1. **🔄 التناوب الذكي والسريع بين روابط الـ RPC (RPC Rotation Pool)**:
   - يتناوب تلقائياً بين الروابط المجانية والسريعة (LlamaNodes, Ankr, Cloudflare, PublicNode, BlastAPI, Flashbots) ومفاتيحك الخاصة (Alchemy / Infura).
   - إذا حصل `Rate Limit` أو انقطاع على رابط معين، ينتقل فوراً للرابط التالي خلال أجزاء من الثانية دون أن يتوقف البوت أو يبطئ.

2. **🌐 دعم المينت الشامل (Universal Mint Protocol)**:
   - **المسار الأساسي:** شراء مينتات **OpenSea SeaDrop** بأقصى سرعة بالميلي ثانية.
   - **المسار الشامل الذكي:** صيد المينتات المجانية على المنصات الخارجية والعقود المباشرة مثل **(Zora Protocol, Manifold, و Direct Public Mints)** عبر فحص مسبق فوري للغاز والتأكد أنها مجانية 100%.

3. **⛓️ دعم شامل للشبكات (Multi-Chain)**:
   - **Ethereum Mainnet** (Chain ID 1)
   - **Robinhood Chain Mainnet** (Chain ID 4663)
   - **Arc Mainnet** (Chain ID 5042)
   - **Ink Mainnet** (Chain ID 57073)

4. **👛 دعم المحافظ المتعددة وبوتات التيليجرام المنفصلة**:
   - إمكانية ربط حتى 10 محافظ أو أكثر.
   - لكل محفظة يمكن تخصيص بوت تيليجرام خاص بها يرسل إشعارات الشراء لصاحبها مباشرةً، أو استخدام بوت عام موحد.

5. **🐦 فحص حساب X (تويتر)**:
   - فحص اختياري: يجلب حساب X/Twitter من OpenSea Collections API، ثم يتحقق منه عبر X API عند توفير `TWITTER_BEARER_TOKEN` (`CHECK_TWITTER=true/false`).

---

## 🛠️ التثبيت والتشغيل

1. **تثبيت المتطلبات**:
```bash
pip install -r requirements.txt
```

2. **إعداد ملف المتغيرات**:
انسخ ملف `.env.example` إلى `.env` وقم بملء مفاتيحك:
```bash
copy .env.example .env
```

3. **خيارات التحكم في ملف `.env`**:
* `BOT_ENABLED=true` (تفعيل الشراء الحقيقي).
* `ENABLE_UNIVERSAL_MINTS=true` (تفعيل الشراء الشامل لـ Zora و Manifold والعقود المباشرة).
* `CHECK_TWITTER=false` (تعطيل فحص تويتر للسرعة القصوى، أو `true` للأمان الإضافي).

4. **تشغيل البوت**:
```bash
python main.py
```

## إعدادات RPC ومفاتيح OpenSea المتعددة

يمكن وضع عدة روابط RPC عامة أو خاصة لكل شبكة في متغيرات `*_RPC_URLS`، وتفصل الروابط بفواصل، مثل: `INK_RPC_URLS=https://rpc-gel.inkonchain.com,https://rpc-qnd.inkonchain.com`. ويتم تدوير الروابط تلقائيًا عند بدء الاتصال. كما يمكن وضع عدة مفاتيح OpenSea في `OPENSEA_API_KEYS=key1,key2,key3`، وسيتم تدويرها بين طلبات Drops وWebSocket. روابط المعاملات في إشعارات تيليجرام تفتح مستكشف الشبكة العام المناسب.


## تحسينات السرعة

تم تحسين المسح الدوري ليجلب صفحات OpenSea بالتوازي، ويمنع معالجة الدروب المكرر، ويستخدم اتصالات HTTP مستمرة مع DNS cache. ولتقليل زمن الإرسال يمكن تفعيل `SKIP_BALANCE_CHECK_RACE=true` و`FIXED_GAS_LIMIT=185000` كما في نموذج البيئة؛ وللتحقق الأكثر تحفظًا استخدم `SKIP_BALANCE_CHECK_RACE=false` و`FIXED_GAS_LIMIT=0`.

عند تفعيل الخيارين السابقين معًا، يدخل البوت **وضع الإرسال السريع**: يتجاوز فحص فتح المرحلة وفحص الرصيد والغاز المسبقين المكررين، ويترك رفض المعاملة للعقدة إذا كانت المرحلة غير مفتوحة أو الرصيد غير كافٍ. كما يرفع معدل كشف OpenSea بحسب عدد المفاتيح عبر `OPENSEA_RATE_PER_KEY`؛ إذا ظهر `HTTP 429` فاخفض القيمة.

لإعداد أقصى أداء، استخدم القيم الموجودة في `MAX_PERFORMANCE.env.example`، أو انسخها إلى `.env`. الإعداد يعطل فحص X ويجعل المسح كل ثانية ويستخدم حد الغاز الثابت. يفضل استخدام RPC خاص سريع؛ وإذا ظهر `HTTP 429` خفّض `OPENSEA_RATE_PER_KEY` إلى `2` أو `1.5`.

## التنفيذ عند فتح المرحلة

لا يعتمد البوت الآن على وصول أول عملية سك أو حدث بيع لبدء المحاولة. عند اكتشاف مرحلة مجانية مستقبلية، يسجل وقت `start_time` وينشئ مهمة انتظار مستقلة، ثم يعيد جلب بيانات الدروب ويبدأ مسار السحب مباشرة بعد فتح المرحلة ببضعة أجزاء من الثانية. تبقى إشعارات WebSocket والماسح الدوري كمسارات احتياطية، وتمنع آلية المفاتيح المزدوجة تشغيل نفس الدروب أكثر من مرة.

## تشخيص إشعارات البدء والمفاتيح

عند التشغيل سيظهر في اللوج عدد مفاتيح OpenSea التي تم تحميلها، وعدد وجهات Telegram، ونتيجة إرسال إشعار البدء. إذا لم توجد محافظ بعد، يمكن استخدام الوجهة العامة مباشرة عبر `TELEGRAM_BOT_TOKEN` و`TELEGRAM_CHAT_ID`. وإذا رفض Telegram الرسالة فسيظهر رمز HTTP ووصف الخطأ في اللوج بدل تجاهله.

## البنية الاحترافية والاعتمادية

> يستخدم Stream endpoint الرسمي الحالي مع تصفية server-side على `item_transferred` فقط؛ وهذا يقلل ضغط الرسائل ويمنع امتلاء حد الإرسال في OpenSea.


- `buyer.py`: تنفيذ المعاملة، SeaDrop، وفحص الرصيد والغاز.
- `main.py`: الماسح، OpenSea، WebSocket، المهام والتنبيهات.
- `runtime_config.py`: سجل الشبكات والتحقق من Chain ID وRPC قبل التشغيل.
- `key_pool.py`: تدوير مفاتيح OpenSea مع استبعاد المفتاح المحدود مؤقتاً عند HTTP 429.
- `test_professional_config.py`: فحوص الإعدادات الأساسية قبل التشغيل.

| الشبكة | Chain ID | متغيرات RPC | المستكشف |
|---|---:|---|---|
| Ethereum Mainnet | 1 | `ETHEREUM_RPC_URLS` | Etherscan |
| Robinhood Chain | 4663 | `ROBINHOOD_RPC_URLS` | Blockscout |

يتم تجربة الروابط بالتناوب، وتوضع الروابط الفاشلة في **تبريد تدريجي** لمدة قصيرة قبل إعادة استخدامها. لا تضع المفاتيح الخاصة أو مفاتيح API داخل الكود أو Git؛ استخدم ملف `.env` محلياً.

## إعدادات السرعة

ضمن النطاق الحالي، الماسح لا يترك endpoint المينتات النشطة لطلب عام بالتناوب؛ يعمل Stream والـ REST scanner معاً لتقليل فقدان الفرص أثناء إعادة الاتصال. يظل OpenSea نفسه best-effort، لذلك لا يمكن ضمان أحداث مفقودة أثناء انقطاع الخدمة دون مراقبة on-chain.


للاكتشاف السريع استخدم: `PERFORMANCE_PROFILE=ultra`، حيث تصبح دورة الماسح 0.25 ثانية مع مهلة WebSocket ثانية واحدة وتوازي أعلى. ولأسرع إرسال للمينت، يمكن استخدام `SKIP_BALANCE_CHECK_RACE=true` و`FIXED_GAS_LIMIT` بعد التأكد من الرصيد وحد الغاز.

`RACE_MODE=true` يجهّز المعاملات قبل فتح المرحلة، لكنه قد يرسل أكثر من محاولة؛ لذلك يجب مراقبة الغاز واستخدامه فقط عندما تكون هذه المخاطرة مقصودة.

## مراقبة المعاملات المعلقة اختيارياً

يدعم المشروع الآن مراقبة `newPendingTransactions` عبر WSS للعقود التي يكتشفها OpenSea/REST. ضع رابط WSS سريعاً لكل شبكة في `.env` لتفعيلها. عند عدم وضع الروابط، تبقى مراقبة OpenSea وREST فعالة كالمعتاد. المراقب لا يرسل معاملة بمجرد رؤية pending؛ يعيد فحص المرحلة والسعر والأهلية وقفل التكرار أولاً.
